# 情報量の見直し（minimal_information_design）記録：QRいっき読み v0.4.3

- 実施日：2026-11-24
- 対象：アプリ全体（スキャン／作る／宝箱／設定＋結果シート＋各ダイアログ＋空状態）
- 手法：カスタムスキル `minimal_information_design`（コンセプト仕分け → 対照表 → 重複排除 → 置換・圧縮 → 検証）
- 前提：v0.4.2 の挙動（自動保存トグル既定 ON、検出時プレビュー：リスト＝2：3、全13形式・アクション・警告表示）は維持。機能は消さない。配色は ART_DIRECTION の藍系トークンのまま。

## 1. コンセプト（判定軸、正本 `docs/MVP_SPEC.md` §1）

「QRコードとバーコードについて『読む・作る・整える・管理する・守る』の全部を、端末内だけで、最速の手数でできる道具。」

| 要素 | 内容 |
| --- | --- |
| 誰 | 日常で QR を読み書きする一般ユーザー／コードを大量に扱う現場スタッフ |
| 場面 | 店頭・レジ前、チラシ／ポスターの前、会議資料、商品パッケージ、棚の前 |
| 行為 | かざして読む／作る／宝箱から再利用する |
| 状態・気持ち | 「合わせ直す」「探す」「迷う」が消え、一息で終わる |
| 最優先の価値 | 最速の手数／端末内完結（安全） |

判定文の型：「これが無くなると、コンセプトの［要素］が成立しなくなる」。

### 検討して残したもの（理由つき）

- S5／S6 許可の理由文2つ：プライバシー（端末内完結）はコンセプトの核であり、許可判断の場面が正本。2文目は「許可しない場合に使える範囲」という差分情報を持つ。
- R2 形式名：注記レベルに降格済み（チップの隣の小文字）。形式の区別（EAN-13 と UPC-A 等）が判断材料になる場面があるため残す。
- R8 連絡先の読み取り項目と R10 生データの併存：読み取り項目は「追加前に人が確かめる形」、生データは項目化されていない要素（メモ欄・住所等）を含む検証面で、差分がある。
- S11／S12 の小さなラベル（ライト／ズーム）：アイコンだけでは初見で意味が固定しない操作の補助として残す（スキルの「アイコン＋短いラベル」容認）。
- S15 の「（タップで開く）」：live region の読み上げ文を兼ね、初回利用の案内でもあるため残す（下記 J-3）。
- C11 詳細設定内の説明2つ：折りたたみを開いた＝選択の瞬間にだけ出る補助であり、常時表示ではないため残す。
- C1 プレビュー下の要約：入力欄の値ではなく「生成された payload の正体」の表示であり、Wi-Fi 等では入力と形が違うため検証として残す。
- T11 アプリ情報文：プライバシー説明の正本。設定という「別場所」に集約された低頻度情報として残す。

### 検討して残したもの（理由つき）

- 重複の三重伝達（振動2連＋バナー＋DuplicateChip）：時点と媒体がすべて違う。振動は目を離した作業中の非視覚チャネル、バナーは読み取り時点の警告、チップは後から見返す記録側の目印。どれかを消すと、その時点・媒体での伝達が消えるため一本化しない。バナーの文だけ N3-5 で圧縮した。
- 台帳詳細のメタ行の「未終了」：再開／終了ボタンも同じ状態を示すが、メタ行は「開始〜終了」の期間表示の完結形として残す（ボタンは操作、メタ行は記録の要約であり役割が違う）。
- モード帯（待機）の「台帳（0）」：台帳が0冊でも出す。連続スキャンの置き場の発見（どこに溜まるか）を兼ね、空の一覧には次の行動のガイド（P17）があるため、行き止まりにならない。
- 連続モード中の無効化された画像読込／カメラ切替ボタン：第2回の R2-7 方針（無効化で「今は使えない」を示す）を維持。
- 台帳詳細のボタン5つ（続ける／終了する／CSV／名前を変える／削除）：未終了時は5つ、終了後は3つ。低頻度の管理2つ（名前・削除）は補助ボタンの格で並び、主役（CSV／続ける）を遮らないため現状維持。折りたたみへの移設は到達ステップを増やすだけで情報量は減らない。
- P12 台帳一覧の見出し「台帳」：第1回で消した設定見出し（T1）とは違い、ここは下部タブに現れないサブビューであり、画面名の正本が他に無いため残す。
- J-2／J-3、J-B1／J-B2：本人の未決定事項であり、今回も参照のみで実装しない（§5、docs/BEGINNER_REVIEW_2026-11-25.md）。
